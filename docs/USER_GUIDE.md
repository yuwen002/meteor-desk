# MeteorDesk 详细使用手册

> 本手册面向日常使用者，按界面功能说明入口、操作步骤、结果含义和常见问题。界面名称可能随版本小幅调整；请以当前安装版本实际显示为准。

## 1. 产品简介与数据安全

MeteorDesk 是运行在本机的开发与运维桌面工作台，主要包含：

- **日志分析**：打开本地日志、文本/正则检索、上下文查看、多行 JSON 文档检索、增量结果、取消搜索。
- **进程管理**：维护本地服务配置、启动/停止/重启服务、查看标准输出和错误输出，并按依赖关系编排启动顺序。
- **开发工具**：时间戳与时区转换、JSON 格式化/压缩/对比、Base64 编解码、JWT 载荷查看、URL 与查询参数解析。
- **工作台设置**：深浅色主题、快捷键配置、最近文件、检索历史以及配置导入/导出（以当前界面提供的操作为准）。

应用通过 Wails 在本机运行，不提供给外部客户端使用的 REST/HTTP API。日志和开发工具输入默认在本机处理；使用前仍应遵守所在组织对敏感日志、令牌和配置文件的安全要求。

## 2. 启动、退出与界面导航

### 2.1 启动应用

1. 从项目发布页或组织提供的位置获取与你的操作系统匹配的桌面构建。
2. 按操作系统要求启动应用；首次启动时，系统可能提示确认应用来源或授予文件访问权限。
3. 等待主窗口出现。顶部状态区域用于显示本机运行状态，左侧导航用于切换功能页面。
4. 若应用无法启动，先确认下载的构建与操作系统、CPU 架构匹配，再查看系统安全提示和应用日志。

开发者如需从源码启动，请先安装 Go、Node.js/npm、Wails v2 及操作系统对应的桌面开发依赖，再按仓库 README 的开发命令执行。

### 2.2 页面导航

- **日志分析**：检索日志文件、定位匹配行和查看上下文。
- **进程管理**：配置和管理本机子进程/开发服务。
- **开发工具**：使用时间、JSON、Base64、JWT、URL 等转换工具。

切换页面不会把本机文件自动上传到服务器。正在运行的本地服务不会因为切换页面就自动停止。

### 2.3 深色与浅色主题

1. 点击顶部工具栏的太阳/月亮图标。
2. 图标切换后，应用外层和各功能面板应同步切换主题。
3. 主题偏好保存在本机；重新打开应用后会尝试恢复上次选择。
4. 如果某个内嵌区域仍然保持另一种主题，请记录页面名称、操作步骤和截图，作为界面问题反馈。

主题仅影响显示，不改变检索、转换或进程运行结果。

## 3. 日志分析

### 3.1 打开日志文件

1. 进入“日志分析”页面。
2. 点击打开文件/选择文件入口，在系统文件选择器中选择要分析的日志。
3. 也可以将日志文件拖放到应用支持的文件区域。
4. 文件打开后，检查页面显示的文件路径、大小或状态信息，确认选中了正确文件。

建议先从较小的文件验证查询条件，再对大文件执行检索。应用按流式方式读取日志，避免一次性把整个大文件加载到内存中；但检索仍会消耗磁盘 I/O 和 CPU。

**注意：** 如果日志文件正在被其他程序写入，当前检索读取的是本次打开/检索过程中实际读到的内容；需要检查最新日志时，重新执行检索或重新打开文件。

### 3.2 实时日志跟踪

1. 先选择一个本地日志文件。
2. 在“实时日志跟踪”面板点击“开始跟踪”。首次启动从当前文件末尾开始，只显示后续追加的内容，避免一次加载整个历史日志。
3. 使用“暂停”暂时停止轮询，“继续”恢复跟踪；“停止”结束本次跟踪，“清屏”只清除当前界面缓存，不会修改磁盘上的日志文件。
4. 跟踪输出保留最近约 1 MiB 内容，超过后会丢弃较旧的显示内容，以控制内存占用。
5. 多标签页各自保存实时跟踪的读取偏移、输出缓存、暂停状态和级别筛选。切换到其他标签时，后台标签会暂停轮询；切回仍处于跟踪状态的标签后继续读取，不会从文件末尾重新开始。关闭标签会结束该标签的跟踪状态。
6. 如果文件被截断，或原路径被轮转后的新文件替换，跟踪会尝试从新文件头重新读取。
7. 使用“全部”“INFO”“WARN”“ERROR”按钮筛选实时输出；级别识别支持常见文本前缀、方括号标记和 JSON `level`/`severity` 字段。未识别的行只在“全部”视图显示。过滤只影响界面显示，不会更改日志文件或读取偏移。

当前版本跟踪本地普通文件，按约 700 毫秒间隔轮询，并通过文件身份比较识别常见的路径替换轮转（包括新文件比旧偏移更大的情况）。如果轮转工具采用特殊的复制/截断方式，仍建议观察输出连续性；跟踪失败时请检查文件是否被删除、权限是否变化以及路径是否仍有效。

### 3.3 输入检索关键词

1. 在检索输入框输入关键字，例如 `ERROR`、`connection refused` 或业务 ID。
2. 默认文本检索会查找包含该字符串的内容。“区分大小写”选项默认开启；关闭后，普通文本检索会忽略英文 ASCII 字母大小写，正则检索会使用 Go/RE2 的大小写折叠规则。该选项会保存在本机设置中。
3. 点击检索按钮或使用当前界面显示的对应快捷键开始检索。
4. 查看匹配数量和结果列表；点击某条结果可定位到对应日志位置（具体交互以当前界面为准）。

建议使用足够独特的关键字。若结果过多，可增加错误码、服务名、请求 ID 等条件；若没有结果，检查大小写、空格、编码和关键词是否真实存在于文件中。

检索完成后，匹配关键词会在结果行中高亮显示；启用正则表达式时也会尝试按正则模式高亮。高亮只改变显示，不会修改原始日志。可在结果筛选区域的“排除关键词”输入一个或多个词，用逗号或换行分隔；包含任一排除词的结果会隐藏。清空排除词即可恢复。排除条件与时间范围、日志级别筛选组合生效，匹配总数显示的是当前筛选后的结果数。排除关键词、日志级别以及起止时间会保存在本机设置中，重新启动后会尝试恢复。最近文件若已被移动或删除，启动时会检查路径并清理失效记录；若没有可用的最近文件，会提示重新选择。

可在检索结果上方设置开始和结束时间，按日志行中的时间戳缩小当前结果。支持 ISO 8601、`YYYY-MM-DD HH:mm:ss`、Apache 时间戳，以及 JSON 的 `timestamp`、`@timestamp` 或 `time` 字段。日期时间输入按本机时区解释；日志行带时区时按其时区转换比较。设置结束时间会包含所选分钟内的全部秒数。开启时间范围后，无法识别时间戳的行会隐藏；清除时间范围即可恢复全部匹配。该筛选仅作用于当前检索返回的结果，不会再次扫描文件。检索结果也可按 INFO、WARN 或 ERROR 级别筛选；级别和时间条件会同时应用。选择“全部”恢复所有级别。

检索完成后会显示“当前检索结果统计”面板，统计当前筛选后、已加载的结果中 INFO/WARN/ERROR 和未识别级别的数量；如果日志能解析出时间戳，面板会按分钟汇总最多 60 个时间桶，并按归一化后的消息展示最多 10 组重复错误。统计不重新扫描文件，也不代表整份文件的完整总量；如果结果上限截断或检索被取消，请先确认结果状态再解读统计。

### 3.4 正则表达式检索

1. 在检索选项中启用“正则”模式。
2. 输入 Go/RE2 风格正则表达式。
3. 执行检索并检查匹配结果。

示例：

| 目的 | 表达式示例 |
|---|---|
| 匹配 ERROR 或 FATAL | `ERROR|FATAL` |
| 匹配 HTTP 5xx 状态码 | `\b5[0-9]{2}\b` |
| 匹配 UUID 形式的标识 | `[0-9a-fA-F]{8}(-[0-9a-fA-F]{4}){3}-[0-9a-fA-F]{12}` |

正则表达式的语法与浏览器 JavaScript 正则并不完全相同；Go 的正则引擎使用 RE2 语法，不支持回溯引用和部分高级断言。表达式无效时，先简化表达式，再逐步增加条件。

### 3.5 字符编码

如果日志出现乱码或无法匹配中文：

1. 打开检索选项中的编码设置（若当前界面提供）。
2. 优先尝试自动识别。
3. 如果已知文件编码，可明确选择对应编码后重新检索。
4. 对于由其他系统导出的 UTF-16 等日志，确认编码选择与实际文件一致。

编码自动识别只能根据文件内容进行判断，不保证对所有混合编码或损坏文件都正确。遇到异常时，先确认原始文件编码。

### 3.6 检索上下文

上下文用于查看匹配行前后发生了什么：

1. 在上下文行数选项中设置需要显示的前后行数（如果界面提供该选项）。
2. 重新执行检索。
3. 在结果详情中查看匹配行及其上下文。

例如，排查“连接失败”时，可以同时查看失败前的连接参数日志和失败后的重试日志。上下文行不是额外匹配结果；不要把上下文数量当成匹配条数。

### 3.7 多行 JSON 文档检索

此模式适用于一个 JSON 对象或数组跨多行排版的日志，例如：

```json
{
  "level": "error",
  "message": "database unavailable",
  "details": {
    "retry": 3
  }
}
```

操作步骤：

1. 打开日志文件。
2. 在检索选项中启用“多行 JSON”（该选项为可选模式）。
3. 输入要查找的字段名或文本内容，例如 `database unavailable`。
4. 执行检索。完整 JSON 对象/数组作为一个匹配单元，结果定位到该文档的起始行。
5. 如需普通日志行也参与检索，确认文件中的普通行没有被误认为 JSON 文档；混合日志中的普通行仍支持检索。

使用限制和注意事项：

- 文档可以是跨行对象或数组，也支持嵌套对象/数组。
- JSON 字符串内部的括号字符不会单独结束文档。
- 单个多行 JSON 文档最大为 **4 MiB**；超过限制会停止本次检索并返回明确错误，避免内存占用失控。
- 多行 JSON 模式同样支持前后 0、2、5、10 行上下文；上下文只取 JSON 文档外的普通日志行，不会把同一 JSON 文档内部行或相邻 JSON 文档的内容重复展示为上下文。
- 为保证增量结果与最终结果一致，开启后文时，命中结果会在收集到所需后文或扫描到文件末尾后推送；达到结果上限后仍会读取必要的普通日志行来补齐已命中结果的上下文。
- 如果文件结束时文档仍未闭合，该不完整文档不会作为完整 JSON 匹配结果返回。
- 该模式用于按文档聚合检索，不等于完整 JSON Schema 校验；如果需要验证 JSON 的业务结构，应使用 JSON 工具或专用校验工具。

### 3.8 查看进度、取消检索和增量结果

1. 开始检索后，观察进度和已找到的结果。
2. 如当前任务耗时过长，可使用界面中的取消操作。
3. 取消后，检索应停止继续读取；取消前已经产生的匹配结果会尽可能保留。
4. 如果需要更完整的结果，调整关键词或模式后重新执行检索。

取消操作不代表“没有匹配项”。应结合已显示的结果、取消状态和扫描进度判断本次检索是否完整结束。

### 3.9 结果上限与大文件建议

为限制内存占用，结果数量受应用硬上限约束。达到上限时，结果可能显示“已达到结果上限”或相应提示，此时结果列表不是文件中所有匹配项的完整清单。

结果列表上方提供“跳转结果”：输入当前筛选结果中的序号（从 1 开始），按回车或点击“跳转”，即可选中目标匹配项并在虚拟滚动列表中定位。序号范围以当前过滤后的结果数量为准；切换时间、日志级别或排除词后，应按新的结果总数选择序号。达到结果上限或取消检索时，跳转范围只覆盖本次已经返回的匹配项，不代表文件中尚未加载的结果。\n\n处理大文件建议：

- 尽量用请求 ID、时间片段、错误码等缩小范围。
- 优先用普通文本检索；只有需要跨行匹配时才开启多行 JSON。
- 对超长单行或超大 JSON 文档，根据提示拆分文件或改用更合适的处理方式。
- 运行期间避免同时对同一块磁盘执行过多大型检索。

### 3.10 最近文件与检索历史

如果页面显示“最近打开的文件”或“最近检索”：

- 点击历史项可以重新打开对应文件或恢复之前的检索条件。
- 历史记录只是一种快捷入口；原文件移动、改名或删除后，历史路径可能失效。
- 检索历史中的条件可能包含业务关键词。请按本机使用环境的敏感信息规范管理应用配置，不要在共享屏幕或截图中暴露敏感内容。

## 4. 本地进程管理

> 进程管理会真实启动和停止本机程序。执行前确认命令、参数、工作目录和环境变量，避免停止重要服务或启动错误程序。

### 4.1 新增或编辑进程配置

1. 进入“进程管理”页面。
2. 点击新增配置或编辑现有配置。
3. 填写服务名称，便于在列表中识别。
4. 填写可执行命令或程序路径。
5. 填写命令参数；每个参数应按界面规定单独填写，不要把参数错误地拼成可执行文件名。
6. 设置工作目录。相对路径通常依赖工作目录，建议使用明确的绝对路径。
7. 如有需要，填写环境变量或启动依赖。
8. 保存配置后，检查列表中的命令、目录和依赖关系是否正确。

不要将密码、访问令牌等秘密硬编码进可共享的配置文件。环境变量配置同样可能包含敏感值，应限制文件访问权限。

### 4.2 启动、停止和重启

- **启动**：选择目标服务，执行启动操作。启动前检查命令、工作目录和依赖服务状态。
- **停止**：选择正在运行的服务，执行停止操作。确认该进程确实由 MeteorDesk 管理，并评估停止对其他任务的影响。
- **重启**：用于配置更新后重新运行服务。重启前保存需要保留的工作，确认服务中断可接受。
- **批量操作**：如果界面提供批量启动或停止，先确认选择范围，避免对无关服务操作。

进程启动成功不一定代表业务服务已完全就绪；必要时还应检查服务端口、健康检查或实际请求结果。

### 4.3 标准输出与错误输出

1. 在进程列表中选择服务。
2. 打开该服务的输出/日志区域。
3. 通过标准输出（stdout）查看程序常规运行信息。
4. 通过标准错误（stderr）查看错误、告警或诊断信息。

有些程序会把日志统一写入 stdout，也有程序把全部内容写入 stderr；因此不要仅凭输出通道判断是否发生故障。若进程很快退出，先检查 stderr 中的启动错误，再核对命令和工作目录。

### 4.4 依赖关系与启动顺序

当服务依赖数据库、缓存或其他本地服务时：

1. 在服务配置中为依赖方声明前置服务。
2. 检查依赖关系是否指向正确的服务配置。
3. 启动依赖编排时，先启动被依赖的服务，再启动上层服务。
4. 如果启动失败，逐一检查依赖服务是否成功运行，以及端口和环境配置是否正确。

不要建立循环依赖（例如 A 依赖 B，同时 B 又依赖 A）。依赖编排只负责按依赖关系安排进程启动，不会自动保证远程数据库、网络或业务接口健康。

### 4.5 异常退出与排障

如果服务启动后立即停止：

1. 查看 stdout/stderr 最后输出。
2. 检查可执行文件是否存在、是否有执行权限。
3. 确认工作目录存在且进程有权限访问。
4. 检查环境变量、端口占用、配置文件路径和依赖服务状态。
5. 在终端中使用相同命令手动运行，以区分程序自身错误和工作台配置错误。

停止或重启后，应确认列表状态与实际进程状态一致。不要通过反复点击启动来处理未知错误，以免重复启动多个实例。

## 5. 开发工具箱

进入“开发工具”页面后，通过顶部工具标签切换不同工具。多数输入会在本地页面中处理；使用结果前仍需核对输入内容和输出格式。

### 5.1 时间戳 / 时区

**将时间戳转换为日期时间**

1. 选择“时间戳 / 时区”。
2. 输入时间戳数值。
3. 选择单位：秒或毫秒。常见 Unix 时间戳为 10 位秒级或 13 位毫秒级，但位数只是经验，不能替代单位确认。
4. 选择目标时区，例如 `Asia/Shanghai`、`UTC` 或 `Asia/Tokyo`。
5. 查看格式化时间、ISO 时间和换算后的秒/毫秒值。
6. 点击对应复制按钮（如果显示）复制所需结果。

**将指定时区的日期时间转换为时间戳**

1. 在日期时间输入区选择日期和时间。
2. 选择该日期时间所属的时区。
3. 查看转换后的 Unix 时间戳。
4. 若提示时间无效，检查日期是否真实存在，以及时区是否使用 IANA 名称。

注意：时间戳表示绝对时间；同一时间戳在不同的时区显示不同的本地日期时间。夏令时切换时，某些本地时间可能不存在或存在歧义。

### 5.2 JSON 工具

**格式化 JSON**

1. 选择“JSON 工具”。
2. 将 JSON 文本粘贴到输入区。
3. 点击格式化操作。
4. 检查缩进后的输出；若解析失败，错误提示通常会指出 JSON 语法问题。

**压缩 JSON**

1. 在输入区粘贴有效 JSON。
2. 点击压缩操作。
3. 复制压缩后的单行 JSON，用于配置、接口调试或日志比对。

**比较两份 JSON**

1. 将基准 JSON 放在左侧，将待比较 JSON 放在右侧。
2. 确认两侧内容均为合法 JSON。
3. 查看字段路径差异：新增、删除或修改。
4. 对照路径和前后值判断变更是否符合预期。

比较按结构化字段路径进行，而不是简单逐字符比较；对象字段顺序不同通常不会被当成字段值变更。数组按索引比较，因此数组元素位置变化可能产生多项差异。当前实现对比字段数量有约 20,000 个叶子字段的保护限制。

### 5.3 Base64 编码与解码

**编码**

1. 选择“Base64”。
2. 在原文输入区粘贴要编码的文本。
3. 点击编码。
4. 复制 Base64 结果。

**解码**

1. 将 Base64 字符串粘贴到编码输入区。
2. 点击解码。
3. 查看解码后的 UTF-8 文本并核对内容。

Base64 是编码，不是加密；任何拿到编码结果的人都可能将其还原。不要把 Base64 当作保护密码、令牌或隐私数据的安全措施。解码失败时检查字符是否完整、是否误复制了引号或其他文本。

### 5.4 JWT 载荷查看

1. 选择“JWT 载荷”。
2. 粘贴完整 JWT 字符串。
3. 工具解析并展示 Header 和 Payload。
4. 如果 Payload 包含数字类型的 `exp` 字段，会显示对应过期时间以及当前是否已过期。
5. 根据需要复制解析结果。

**重要安全说明：** 此工具用于解码查看，不验证签名，也不证明令牌真实有效。显示“尚未过期”仅表示根据 `exp` 推算的时间尚未到达，不代表令牌未被撤销、签名可信或权限有效。不要将生产环境 JWT 粘贴到共享截图、工单或不受信任的环境。

### 5.5 URL / 查询参数

**解析 URL**

1. 选择“URL / 参数”。
2. 粘贴完整 URL 或查询字符串。
3. 查看 Origin（源）、Path（路径）和 Hash（片段）。
4. 查看 Query 参数列表及对应值。

**编码与解码**

1. 在待处理文本区域输入原文或已编码内容。
2. 使用对应编码/解码操作。
3. 检查输出，确认空格、中文、百分号和特殊字符符合预期。

**复制单个参数**

- 点击参数行旁的复制图标，复制对应参数值。
- 同名参数可能出现多次，检查参数列表中的每一项，不要假设查询参数名称一定唯一。

URL 中可能包含访问令牌、用户标识或签名参数。分享 URL 前先检查并移除敏感参数。

## 6. 快捷键

1. 点击顶部“快捷键”入口。
2. 查看当前操作与快捷键的对应关系。
3. 点击要修改的快捷键并按下新的组合键。
4. 如果出现冲突提示，先为冲突操作分配其他组合键，避免一个组合键触发多个动作。
5. 如需恢复，使用界面提供的恢复默认操作。
6. 保存后，在对应页面测试快捷键是否生效。

快捷键可能因操作系统或桌面环境而受系统级快捷键影响。若某个组合键无法触发，尝试换用不冲突的组合键并重新保存。

## 7. 配置与数据维护

如果当前版本的设置界面提供配置导入/导出：

- **导出前**：检查配置是否包含本机绝对路径、命令参数、环境变量或秘密。
- **导入前**：确认文件来源可信，并检查导入后服务命令、工作目录和依赖是否正确。
- **导入后**：重新检查进程列表和快捷键设置，必要时手动修正路径。
- **备份**：升级或批量调整服务配置前，建议先导出一份可恢复的配置（如果当前界面支持）。

最近文件和检索历史是路径/查询条件的快捷记录，不保证源文件仍存在。清理或迁移本机应用数据前，请先确认是否需要保留相关配置。

## 8. 常见问题

### 找不到文件或打开失败
检查文件路径、访问权限、文件是否被移动，以及操作系统是否允许应用访问该位置。

### 搜索结果为空
确认关键词、正则模式、编码和多行 JSON 选项是否合适。建议先用普通文本模式搜索一个明确存在的短词。

### 正则表达式报错
先用普通文本确认目标文本存在，再逐步构建正则；注意 Go/RE2 与 JavaScript 正则的差异。

### 多行 JSON 检索报超限
单个文档或单行内容超过限制。可拆分文件、缩小检索范围，或切换普通文本检索。

### 取消搜索后仍有结果
这是预期行为：取消前已找到的结果可以保留。检查界面中的取消状态，不能将部分结果视为完整扫描结果。

### 服务启动后立即退出
查看 stderr、命令路径、工作目录、参数、环境变量、端口占用和依赖服务。先在终端用相同命令复现。

### 浅色主题下有区域仍是深色
切换主题后，主页面和内嵌工具都应跟随主题。如果某一区域没有变化，重新切换一次并记录页面、操作和截图；这属于界面样式问题，不影响数据转换本身。

### 时间转换结果与预期相差数小时
确认输入时间戳的秒/毫秒单位，以及目标时区。不要把本地时间直接当作 UTC。

### JWT 显示未过期但接口拒绝
工具不会验证签名或服务端权限。请检查签名、发行方/受众、服务端时钟、令牌撤销状态和实际权限。

## 9. 使用建议

- 日志分析先缩小范围，再使用正则或多行 JSON 等高级选项。
- 进程管理操作前核对命令和工作目录，批量操作前再次确认目标。
- JSON 比较用于结构化排查；重要变更仍应通过测试或业务校验确认。
- Base64 不提供保密性；JWT 查看不等于验证；URL 查询参数可能包含秘密。
- 对生产日志、访问令牌、用户数据和服务配置遵守组织的保密与留存规范。
- 报告问题时尽量提供应用版本、操作系统、复现步骤、错误信息和脱敏截图，不要附带真实密码、令牌或完整敏感日志。
