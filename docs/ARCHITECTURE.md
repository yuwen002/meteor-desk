# MeteorDesk 架构说明

## 分层与调用路径

```text
Vue 3 / TypeScript (frontend/src)
        │ Wails JS bridge: window.go.main.App
        ▼
App (app.go)
  ├── logx     流式日志读取、编码解码、匹配、上下文与增量回调
  ├── process  本地进程生命周期、依赖排序与输出缓存
  ├── httpx    受限的本机 HTTP 请求（开发工具箱）
  └── config   本地偏好、最近文件与搜索历史
        │
        ▼
本机文件系统 / 本机子进程
```

MeteorDesk 不启动供远端访问的 REST API。Wails 暴露的 Go 方法是桌面界面的本地桥接层；文件检索、工具箱变换和进程配置管理都在本机完成。

## 前端组件划分

- `App.vue` 负责页面导航、日志检索状态与结果列表；结果过滤、排序、收藏、聚合统计等纯数据变换放在 `utils/`，可直接单测。
- `components/ProcessManagement.vue` 与 `components/DeveloperToolkit.vue` 各自管理模块状态，由 `App.vue` 通过 `active` / `v-if` 控制切换。
- `components/AboutDialog.vue` 与 `components/ShortcutsDialog.vue` 是自包含对话框：前者挂载时读取运行信息，后者持有快捷键草稿并在校验通过后写入本地存储，通过 `close` / `change` 事件回传给 `App.vue`。
- 单元测试与组件测试与源码同目录（`*.test.ts`），用 `@vue/test-utils` 挂载组件并 mock `window.go.main.App` 桥接。

## 日志检索数据流

1. 前端生成唯一任务 ID，调用 `SearchLogsAdvanced`；Wails `log-search:update` 事件优先推送进度和新增匹配，250 ms 轮询保留为兼容回退。
2. `App` 创建可取消的上下文，将请求转给 `internal/logx`。
3. `logx` 只抽样文件头部（最多 64 KiB）识别编码，再通过固定缓冲读取全文。非 UTF-8 编码由流式解码器转换为 UTF-8；不会把整个文件读入内存。
4. 搜索器按行匹配。普通文本模式不会缓存整行；预览、上下文、结果数和正则模式整行大小都有上限。
5. 可选上下文模式：多行 JSON 按括号深度把文档聚合成整体，事件上下文按时间戳、空行或自定义正则切分事件；两者均为单条 512 KiB、单次检索 32 MiB 的内容预算。未闭合 JSON 内部不按事件边界拆分。
6. 进度回调只携带新增匹配，前端按游标追加。最终 `SearchResponse` 是完整结果和上下文的权威快照。
7. 取消通过 `context.Context` 传递；程序返回已经找到的结果，而不是丢弃已有结果。

### 编码模式

- `auto`：先识别 UTF-8/UTF-16 BOM，再判断明显的无 BOM UTF-16 字节特征；有效 UTF-8 使用原始流，剩余非 UTF-8 文本按 GB18030 解码。
- `utf-8`、`gb18030`、`utf-16le`、`utf-16be`：显式指定编码，覆盖自动判断。
- 自动检测只是启发式策略。对于非中文传统编码或含二进制内容的混合日志，应手动选择；若文件本身是压缩或加密内容，需先转换为文本。

## 工具箱 HTTP 请求

- 前端将方法、URL、JSON 请求头和正文交给 `App.SendHTTPRequest`，只有在用户点击发送时才发起请求。
- `internal/httpx` 校验请求方法与 http/https 协议，限制请求头数量、请求正文 2 MiB、响应正文 2 MiB 和可配置超时（默认 30 秒、上限 120 秒）；不拼接 Shell 命令，也不读取本地文件。
- 重定向默认为跟随并限制 10 次，可在前端关闭后直接返回 3xx；TLS 校验可按请求跳过，仅用于本机自签证书调试。
- 状态码、响应头、正文、最终地址、重定向次数、二进制标记、实际接收字节数与耗时以结构化对象返回；非 2xx 状态不视为传输错误，响应原样返回。
- 请求历史只保存在前端 localStorage，不写入配置文件；请求由桌面进程直接发出，可访问本机与内网地址，界面不做目标白名单。

## 本机服务生命周期

- 前端通过 Wails 桥接调用 `App`，`internal/process` 负责配置校验、依赖关系与启停顺序。
- 程序使用可执行文件与参数数组创建子进程，不默认将用户输入拼为 Shell 命令。
- stdout、stderr 和系统生命周期消息分别采集，并限制单行长度与每个服务的输出缓存上限。
- 进程管理器保留状态/退出原因，应用关闭时会尝试停止由工作台启动的服务。

## 自动重启与健康检查

- 重启策略由 `Spec.Restart` 描述：`none` 不自动重启，`on-failure` 只在非零退出或信号退出时重启；`MaxAttempts` 限制 1–20 次。
- 退出 goroutine 在持有 `m.mu` 时递增 `Restarts`、计算 `NextRestartAt`，再用 `time.AfterFunc` 登记到 `restartTimers`；等待时间是 `restartBackoff(attempt)`，从 1 秒翻倍到 30 秒上限。
- 定时器到期后的 `autoRestart` 会校验实例仍是当前实例、服务未被删除且配置未变，否则放弃；启动、停止、`Restart`、保存配置与删除都会先取消待执行的重启并清零计数，避免“已停止却又被拉起”。
- 正常退出、可执行文件创建失败不进入重启流程；次数用尽时保留最后一次失败状态，并向运行输出追加“自动重启次数已达上限”。
- 健康探测在 `internal/process/health.go`：每个运行实例持有 `probeStop` 与 `probeOnce`，停止或退出时关闭 channel 结束协程；探测结果在 `m.mu` 下写回快照，仅在健康状态变化时调用 `appendOutput`，避免每个间隔刷屏。
- 探测只读：TCP 建立后立即关闭，HTTP 用独立 `http.Client` 带超时只读 32 KiB 正文，不使用应用配置，也不写本地文件；失败只标记 `unhealthy`，不直接触发重启。

## 依赖就绪门槛

- `Spec.ReadyTimeoutSeconds` 仅在服务配置了 `Health` 时有效，范围 0–600；0 保持原有行为，保存时无健康检查的残留值会被归零。
- `StartBatch` 先拓扑排序，再用 `readinessIDsLocked` 找出本次启动中作为上游被依赖的服务；只有这些服务在启动后等待，避免为没有下游的服务增加延迟。
- `readiness.go` 的 `waitReady` 以 50 ms 间隔读取快照：`healthy` 通过；`unhealthy`、实例被替换、进程停止或超时失败。失败会写入上游运行输出，并让下游按既有 `blockedBy` 逻辑跳过。
- 等待在批量启动调用内同步进行，不新增协程；探测仍由 `startHealthProbe` 的后台协程统一驱动，等待只读快照。

## 进程资源采样

- `metrics.go` 的采样协程随每次运行启动，每 2 秒调用一次平台实现 `sampleProcess` 并写回快照；停止或退出时通过 `stopSamplers` 一并关闭探测与采样协程，避免泄漏。
- `CPUPercent` 用两次采样的累计 CPU 时间差除以实际间隔，按单核百分比计算；首次采样只写内存与时间戳，避免把启动前的累计时间当成瞬时占用。
- 平台实现：Windows 用 `GetProcessTimes` 与 `GetProcessMemoryInfo`（工作集），Linux 读 `/proc/<pid>/stat`（用户态时钟固定 100 Hz），macOS 调用系统 `ps -o time=,rss=`；其他平台返回不支持，不影响服务启停。
- 采样只读进程状态，失败时跳过本次写入并保留上一组数值；进程退出后 CPU、内存与采样时间统一清空。
- 每次写入快照时同时追加一个 `ResourceSample` 到实例内的历史窗口，超过 `metricsHistoryLimit`（150 个）只保留最新 5 分钟；`ResourceHistory` 在锁内复制后返回，前端按 3 秒轮询绘制曲线。
- 历史窗口跟随实例生命周期：重新启动会产生新实例并从头积累；进程退出后快照指标清空，但历史保留本次运行的最后一段曲线供事后查看。

## 端口诊断

- `ports.go` 只在需要时调用系统命令，不在采样循环里执行：Windows 解析 `netstat -ano -p TCP`，macOS 优先 `lsof -nP -iTCP -sTCP:LISTEN -Fpc`、回退 `netstat -an -p tcp`，Linux 优先 `ss -ltnp`、回退 `lsof` 与 `netstat`；单次命令 5 秒超时。
- 解析与地址处理都是纯函数（`parseNetstatListeners`、`parseLsofListeners`、`parseSSListeners`、`portFromAddress`），可用固定输出单元测试，不依赖真实端口占用。
- `PortDiagnostics` 在锁内复制配置端口与实例 PID，随后在锁外扫描，避免系统命令阻塞启停；每个端口标记为 `free`、`owned`、`occupied` 或 `unknown`（扫描失败），并单独返回本服务 PID 实际监听的端口。
- 启动后若声明端口被其他进程占用，会在运行输出写入一条提示（含 PID 与进程名），但不会阻止启动；端口声明只用于提示，不会修改启动命令。

## 版本与构建信息

- 版本号只在 `frontend/package.json` 维护：前端通过 `frontend/src/appMeta.ts` 读取它并展示在侧栏与「关于」面板，避免界面与发布版本不一致。
- 发布构建使用 `-ldflags "-X main.appVersion=<version>"` 把版本写入后端；本地 `wails dev` 未注入时显示 `dev`，方便区分开发构建。
- `App.GetRuntimeInfo` 汇总前后端版本、Go 运行时、`GOOS/GOARCH` 与配置目录；只包含环境信息，不读取日志正文、环境变量或凭据。
- 「关于」面板由侧栏版本号或帮助图标打开；复制诊断信息只在本地剪贴板进行，应用不会后台检查更新，也不向外部服务上报信息。

## 导出边界

- 导出文本由前端 `frontend/src/utils/exporters.ts` 生成：检索结果、进程输出各自只做纯数据转换，便于单元测试且不依赖运行时。
- 文件写入统一走 `App.SaveExportFile`：校验格式（`csv` / `json`）、内容上限 32 MiB 与建议文件名，再由系统保存对话框决定路径，以当前用户私有权限写入。
- 导出只包含当前内存中的结果：检索受结果上限与上下文预算约束，进程输出受每个服务 1,500 条缓存限制，不重新扫描日志或回溯已淘汰输出。
- 导出文件与日志原件同等敏感；应用不上传也不自动同步导出内容。

## 实时跟踪

- 前端每秒调用 `App.ReadLogTail`，只携带上次返回的偏移；后端 `logx.TailFile` 用 `ReadAt` 读取新增区间，不缓存也不重扫整份文件。
- 首次跟踪（偏移为负）从文件末尾回退 256 KiB，并丢弃落在行中间的残行；之后偏移只前进到最后一个换行符之后，未写完的行留给下一次调用。
- 编码复用检索的抽样识别；UTF-16 的换行占两个字节，按字节切分会产生乱码，因此明确拒绝，GB18030 在切行后逐行解码。
- 文件变小或偏移超出文件大小时视为截断/替换，返回 `reset=true`；单次读取上限 2 MiB / 5,000 行，超长行只返回前 64 KiB。
- 前端只保留最近 1,000 行，并在切换文件、恢复检索历史或卸载组件时清除定时器，避免多个轮询同时读取同一文件。

## 结果聚合统计

- 聚合在 `frontend/src/utils/aggregate.ts` 完成，全部是纯函数，不新增后端接口也不重读文件；输入是过滤与排序后的结果列表，与虚拟滚动、导出消费同一份数据。
- 级别识别只看行内第一个级别词（`fatal`/`err` → error，`warn`/`warning` → warn），单词边界避免 `information`、`debugging` 被误判。
- 签名归一先去掉日期时间、纯时间戳与级别前缀，再把 UUID 替换为 `<id>`、数字替换为 `<num>`（数字不带尾部边界，因此 `3000ms` 也会归并），最后压缩空白并截断到 80 字符。
- 高频签名只统计 error/warn 行，按次数降序、同频按文本升序取前 5；复制摘要生成纯文本后写入剪贴板，不经过后端。
- 错误时间分布在 `frontend/src/utils/timeDistribution.ts`：复用 `detectLevel` 过滤 error/warn 行，再按行内时间戳分桶；步长从 1 秒到 1 天按跨度自适应，最多 24 格，溢出样本归入最后一桶。时间一律按 UTC 计算，纯时间行锚定 1970-01-01，因此本机时区与夏令时不会影响分桶边界和标签。
- 没有时间戳的 error/warn 行只计入 `undated` 并在面板提示，不簇拥到首桶；柱高按 `maxCount` 归一化，ERROR/WARN 在同一柱内按比例堆叠。

## 状态与数据保留

- 用户偏好和检索历史位于当前用户配置目录下的 `MeteorDesk/settings.json`。
- 服务配置位于同目录下的 `processes.json`。
- 搜索结果只保留在当前应用任务中；任务清理策略限制历史搜索状态的积累。
- 结果收藏保存在前端 localStorage 的 `meteordesk.bookmarks.v1`，按文件路径与行号去重、上限 500 条；不属于后端配置，也不参与导入导出。
- 项目没有默认遥测，也不会将日志内容上传到外部服务。

## 约束与后续方向

- 搜索结果数最多 5,000；每条行预览最多 8 KiB；上下文预览每行最多 1 KiB。
- 事件与 JSON 文档上下文共用单次 32 MiB 总量预算，预算耗尽后命中回退为行预览；自定义事件边界正则限制 512 字节。
- 正则表达式按整行匹配，单行最多 4 MiB；普通文本匹配以固定缓冲区扫描。
- 增量 UI 优先使用 Wails `log-search:update` 事件推送，250 ms 轮询作为兼容回退；任务 ID、共享游标和最终快照用于保护竞态。
- 实时跟踪固定 1 秒间隔读取，只统计已写入换行的完整行；半行、超大增量与 UTF-16 都走明确的上限或拒绝分支。
- 命中高亮、结果内过滤与排序都在前端对已返回结果做纯数据变换：高亮只切分纯文本片段（不拼接 HTML，单行上限 200 段），过滤不重新读文件，虚拟滚动与导出消费同一份列表。
- 聚合统计同样只覆盖当前已返回且通过过滤的结果，不是全文件分布；级别来自文本启发式识别，无级别词的容器日志会落入「其他」，不能替代结构化日志分析。时间分布只认行内可解析的时间戳，缺少时间戳的行不会参与分桶。
- 自动重启最多 20 次、单次退避上限 30 秒；长时间反复崩溃的服务会在次数用尽后停住，需要人工确认根本原因。健康检查间隔最短 1 秒、超时不超过间隔，失败阈值默认 3 次，避免单次抖动即报异常。
- 就绪等待依赖后台探测节奏：等待时间应大于探测间隔，否则可能在首次探测前超时；被依赖服务未配置健康检查时不会等待。
- 就绪等待是同步阻塞调用：最长 600 秒，期间批量启动无法取消；需要提前结束时可先停止上游服务，等待会因实例结束而立即返回。
- 资源数据每 2 秒更新且只覆盖主进程，不包含子进程；数值受采样间隔影响，不能替代系统级监控工具。macOS 采样依赖系统 `ps` 命令。
- HTTP 调试器默认超时 30 秒、上限 120 秒，最多跟随 10 次重定向，请求/响应正文各 2 MiB；响应超限时只保留前 2 MiB 并标记截断，二进制正文额外标记。
- 合成大文件基准不能替代真实线上日志的编码、多行长度、磁盘吞吐和内存画像。
