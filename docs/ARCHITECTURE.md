# MeteorDesk 架构说明

## 分层与调用路径

```text
Vue 3 / TypeScript (frontend/src)
        │ Wails JS bridge: window.go.main.App
        ▼
App (app.go)
  ├── logx     流式日志读取、编码解码、匹配、上下文与增量回调
  ├── process  本地进程生命周期、依赖排序与输出缓存
  └── config   本地偏好、最近文件与搜索历史
        │
        ▼
本机文件系统 / 本机子进程
```

MeteorDesk 不启动供远端访问的 REST API。Wails 暴露的 Go 方法是桌面界面的本地桥接层；文件检索、工具箱变换和进程配置管理都在本机完成。

## 日志检索数据流

1. 前端生成唯一任务 ID，调用 `SearchLogsAdvanced`；Wails `log-search:update` 事件优先推送进度和新增匹配，250 ms 轮询保留为兼容回退。
2. `App` 创建可取消的上下文，将请求转给 `internal/logx`。
3. `logx` 只抽样文件头部（最多 64 KiB）识别编码，再通过固定缓冲读取全文。非 UTF-8 编码由流式解码器转换为 UTF-8；不会把整个文件读入内存。
4. 搜索器按行匹配。普通文本模式不会缓存整行；预览、上下文、结果数和正则模式整行大小都有上限。
5. 进度回调只携带新增匹配，前端按游标追加。最终 `SearchResponse` 是完整结果和上下文的权威快照。
6. 取消通过 `context.Context` 传递；程序返回已经找到的结果，而不是丢弃已有结果。

### 编码模式

- `auto`：先识别 UTF-8/UTF-16 BOM，再判断明显的无 BOM UTF-16 字节特征；有效 UTF-8 使用原始流，剩余非 UTF-8 文本按 GB18030 解码。
- `utf-8`、`gb18030`、`utf-16le`、`utf-16be`：显式指定编码，覆盖自动判断。
- 自动检测只是启发式策略。对于非中文传统编码或含二进制内容的混合日志，应手动选择；若文件本身是压缩或加密内容，需先转换为文本。

## 本机服务生命周期

- 前端通过 Wails 桥接调用 `App`，`internal/process` 负责配置校验、依赖关系与启停顺序。
- 程序使用可执行文件与参数数组创建子进程，不默认将用户输入拼为 Shell 命令。
- stdout、stderr 和系统生命周期消息分别采集，并限制单行长度与每个服务的输出缓存上限。
- 进程管理器保留状态/退出原因，应用关闭时会尝试停止由工作台启动的服务。

## 状态与数据保留

- 用户偏好和检索历史位于当前用户配置目录下的 `MeteorDesk/settings.json`。
- 服务配置位于同目录下的 `processes.json`。
- 搜索结果只保留在当前应用任务中；任务清理策略限制历史搜索状态的积累。
- 项目没有默认遥测，也不会将日志内容上传到外部服务。

## 约束与后续方向

- 搜索结果数最多 5,000；每条行预览最多 8 KiB；上下文预览每行最多 1 KiB。
- 正则表达式按整行匹配，单行最多 4 MiB；普通文本匹配以固定缓冲区扫描。
- 当前增量 UI 使用轮询；后续可评估 Wails 事件推送，前提是保留任务 ID、游标和最终快照的竞态保护。
- 合成大文件基准不能替代真实线上日志的编码、多行长度、磁盘吞吐和内存画像。
