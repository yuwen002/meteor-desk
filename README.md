# MeteorDesk

**本地开发与运维工作台**

MeteorDesk 是一款使用 Go、Wails v2 和 Vue 3 构建的本地桌面工具，面向开发人员和运维人员，集中处理大体积日志检索、本地服务编排和日常开发任务。

## 本轮迭代：v0.5.34

- 服务输出落盘：可为单个服务开启把标准输出/错误写入配置目录 `logs/<服务名>.log`（单文件 64 MiB、轮转保留 3 份），详情显示落盘路径。
- 跨模块双向跳转：进程详情可一键把落盘文件载入日志分析并自动开始实时跟踪；日志分析可按文件路径反查它属于哪个服务并跳回进程详情。
- 运行数据持久化：生命周期时间线升为每服务 200 条写入 `process-events.json`；新增运行历史（每次起止、退出、重启、峰值 CPU/内存，保留最近 100 次）。
- 服务分组（场景）：把若干服务命名成一组并整组按依赖顺序启停，分组只引用服务 ID、与进程配置同目录持久化。
- 端口占用可操作：当占用配置端口的是本工作台托管的另一个服务时，提供按依赖关系「停止该服务」入口。

更早的版本说明以 [CHANGELOG.md](CHANGELOG.md) 为准，本处只保留最近一个版本，避免 README 无限增长。

## 当前功能

### 日志分析

- 普通文本和 Go 正则表达式检索。
- 自动识别 UTF-8/UTF-16 BOM，并对常见中文 GB18030 日志提供流式解码；支持手动覆盖编码。
- 使用 256 KiB 缓冲区顺序扫描；普通关键字可以跨读取块匹配。
- 支持前后 0、2、5、10 行上下文。
- 结果虚拟滚动、行号、结果数量限制和每行 8 KiB 预览上限。
- 支持查看 JSON/NDJSON 单行内容、格式化 JSON，并按字段路径或字段值筛选；可启用多行 JSON 文档检索，命中详情可查看完整文档。
- 可按行首时间戳、空行或自定义正则聚合事件上下文，把异常堆栈等后续行作为同一次命中展示。
- 支持查询进度与取消；正则模式单行上限 4 MiB。
- 检索结果可导出为 CSV（含上下文与事件行）或 JSON（含检索参数与完整匹配），由系统对话框选择保存位置；导出范围跟随当前的过滤与排序。
- 检索结果支持命中高亮、按内容或行号二次过滤、行号升序/降序切换，以及按文件收藏关键行（仅保存在本机）。
- 检索结果可一键生成聚合摘要：统计 ERROR/WARN/INFO 等各级别数量与行号范围，并对 error/warn 行去掉时间戳、UUID 与数字后按错误签名排序 Top 5；摘要可复制为纯文本粘贴到工单或聊天窗口。
- 摘要面板附带错误时间分布：把 error/warn 行按时间戳分桶（步长 1 秒至 1 天自适应，最多 24 格），柱体按 ERROR/WARN 堆叠，缺少时间戳的行单独提示；点击时间格可把结果限定到该时段。
- 实时跟踪按字节偏移增量读取新增完整行，每秒读取一次并可跟随滚动；支持自动识别、UTF-8 与 GB18030，最多保留 1,000 行。

### 本地进程管理

- 保存服务名称、可执行文件、参数数组、工作目录和环境变量。
- 启动、停止、重启服务并查看运行状态与 PID。
- 配置服务依赖，启动时自动按拓扑顺序拉起前置服务；停止依赖项时，先停止依赖它的下游服务。
- 「依赖关系图」按启动顺序从左到右排列服务，箭头指向下游；节点颜色跟随运行状态，循环依赖用虚线标出，点击节点可切换到该服务配置。
- 支持全部启动、全部停止，并显示每个服务的执行结果；检测并拒绝依赖循环。
- 分别收集标准输出、标准错误和生命周期消息，并记录退出码、开始/结束时间和本次运行时长。
- 单行输出最多保存 64 KiB，每个服务在内存中最多保留 1,500 条输出。
- 当前缓存的运行输出可导出为 CSV 或 JSON，导出范围与内存保留一致。
- 可配置异常退出自动重启：首次等待 1 秒，按 2 倍退避最长 30 秒，达到次数上限后停止重试；正常退出、手动停止或修改配置会取消待执行的重启。
- 可配置 TCP 或 HTTP 健康检查，状态显示为探测中、健康正常或健康异常，并写入运行输出；探测失败只提示，不会自动重启服务。
- 带健康检查的服务可设置「上游就绪等待」（0–600 秒）：作为其他服务的前置依赖时，先等待其健康检查通过再启动下游；超时或健康异常会跳过下游，并在运行输出说明原因。
- 服务运行时自动采集 CPU 与内存占用并在列表与详情展示：每 2 秒采样一次，首次只能得到内存，CPU 需要两次采样后才有数值；停止后清空。
- 详情面板绘制最近 5 分钟的资源曲线（最多 150 个点），标注 CPU 与内存峰值、内存变化量；停止后曲线保留本次运行的最后一段，重启后重新积累。
- 详情面板附带生命周期时间线：按时间顺序列出启动、就绪（含启动耗时）、自动重启与退出（含退出码与运行时长）事件，每个服务保留最近 200 条并持久化到 `process-events.json`，应用重启后仍可回看。
- 运行历史：每次运行结束时汇总起止时间、退出原因与码、自动重启次数与峰值 CPU/内存，本机保留最近 100 次写入 `run-history.json`，并在详情面板展示。
- 输出落盘：服务可勾选把本次运行输出按行追加写入 `logs/<服务名>.log`（单文件 64 MiB、轮转保留 3 份），并可一键在日志分析中打开该文件、复用实时跟踪；日志分析打开落盘文件时可反查归属服务并跳回进程管理。
- 服务分组（场景）：把若干服务存成命名分组，可整组按依赖顺序启停；分组只引用服务 ID、与进程配置同目录持久化，删除分组不影响服务本身。
- 可声明服务监听端口（最多 20 个）；启动时若端口已被其他进程占用，会在运行输出提示占用 PID 与进程名，但不阻止启动。
- 详情面板的「端口诊断」列出配置端口的空闲/本服务监听/被占用状态，并展示本服务进程实际监听的端口，可手动刷新；当占用者是本工作台托管的另一个服务时提供「停止该服务」入口。
- 配置仅保存到当前用户的本机配置目录；服务不会因为保存配置而自动执行。
- 关闭应用时会取消正在运行的日志检索，并尝试停止由 MeteorDesk 启动的服务。
- 进程通过可执行文件和参数直接启动，不会把输入默认拼接为 Shell 命令。

### 开发工具箱

- 时间戳秒/毫秒与 IANA 时区之间转换，支持指定时区的日期时间转 Unix 时间戳。
- JSON 格式化、压缩，以及基于字段路径的新增/删除/修改对比。
- Base64 编码/解码，按 UTF-8 处理中文文本。
- JWT Header/Payload 解码及 `exp` 过期时间提示；**不验证签名，也不保证载荷可信**。
- 解析完整 URL 和 query string，支持 URL 组件编码/解码。
- Cron 表达式解析：标准五段（分 时 日 月 周）语义说明，并按本机时区列出接下来的 8 个执行时间（可单独复制 ISO 时间）。
- 文本差异比较：按行对比两段文本并以 +／- 标记新增与删除，适合配置、响应与日志片段，单次最多 2,000 行。
- 日志脱敏：替换 JSON 字段、键值对、`Authorization`、URL 查询参数与私钥块里的敏感值并统计替换次数；处理全在本机内存完成。
- HTTP 调试器：选择方法、填写 JSON 请求头和正文，显式发送请求并查看状态码、响应头、响应正文、耗时与接收字节数；可配置 5 至 120 秒超时、是否跟随重定向以及本机自签证书场景下的 TLS 校验跳过，最近 10 条请求保存在本机。支持导入 cURL 命令回填表单，或把当前请求生成可复制的 cURL 命令。
- 转换在本机完成，不调用外部服务；不要将私钥或敏感 Token 粘贴到不可信环境。

### 桌面体验与本地配置

- 原生拖放文件打开。
- 最近文件、检索历史、上下文行数和结果上限持久化。
- 常用快捷键：Ctrl/⌘+O 打开文件，Ctrl/⌘+K 聚焦搜索，Ctrl/⌘+Enter 检索，Ctrl/⌘+1/2/3 切换模块。
- 深色/浅色中文工作台界面，主题偏好保存在本机。
- 「关于」面板展示版本与运行环境，诊断信息可复制，不会自动联网检查更新。

- Windows 使用 WebView2；macOS/Linux 使用系统 WebKit

## 环境准备

请先安装 Go、Node.js LTS、npm，以及对应操作系统的桌面开发依赖。参见 [Wails v2 官方安装文档](https://wails.io/docs/gettingstarted/installation)。仓库依赖固定为 Wails v2.10.2，建议本地 CLI 也使用相同版本，避免本地生成与 CI 构建行为不一致：

```bash
go install github.com/wailsapp/wails/v2/cmd/wails@v2.10.2
```

确保 Go 的 bin 目录位于 PATH 中；Windows 通常是 `%USERPROFILE%\\go\\bin`，macOS/Linux 通常是 `$(go env GOPATH)/bin`。CI 通过固定版本的 `go run ...@v2.10.2` 构建，不依赖开发者机器上的全局 CLI 版本。

## 开发启动

在仓库根目录执行：

```bash
cd frontend

npm run lint
npm test

cd ..

go mod tidy
gofmt -l -s $(git ls-files '*.go')   # 输出为空即通过
go test ./...
wails dev
```

```bash
cd frontend
npm install
npm run build
cd ..

wails build
```

## 发布版本

推送与 `frontend/package.json` 版本一致的 tag（例如 `v0.5.23`）会触发 `发布` 工作流：产出四个安装包（Linux amd64、Windows amd64、macOS arm64 与 macOS amd64），校验版本一致后自动创建 GitHub Release，并附带 `SHA256SUMS.txt` 校验和；Release 说明会列出每个包的适用架构与系统前提。

版本号只有一个来源：`frontend/package.json`。界面从该文件读取版本，构建时由 `-ldflags "-X main.appVersion=..."` 注入后端；本地 `wails dev` 未注入时显示 `dev`。Release 说明由工作流从 `CHANGELOG.md` 提取对应版本段落，因此发布前请先补全变更记录。

工作流也支持在 Actions 页面手动触发（选择 `发布` → Run workflow → 填写 tag），用于重跑构建或补发资产，无需删除并重推 tag。完整步骤见 [贡献指南](CONTRIBUTING.md)。

## 大文件性能基准

默认本地基准会生成并扫描约 64 MiB 的合成日志；GitHub Actions 会执行约 1 GiB 的合成日志全量扫描：

```bash
go test ./internal/logx -run '^$' -bench BenchmarkSearchFileLargeLog -benchtime=1x -benchmem
```

内存和磁盘空间允许时，可提高到约 1 GiB：

```bash
# macOS / Linux
METEORDESK_BENCH_SIZE_MB=1024 go test ./internal/logx -run '^$' -bench BenchmarkSearchFileLargeLog -benchtime=1x -benchmem

# PowerShell
$env:METEORDESK_BENCH_SIZE_MB = "1024"
go test ./internal/logx -run '^$' -bench BenchmarkSearchFileLargeLog -benchtime=1x -benchmem
```

## 配置保存位置

应用偏好设置与进程配置保存在当前用户系统配置目录下的 `MeteorDesk` 子目录中，分别为 `settings.json` 和 `processes.json`；生命周期时间线、运行历史与服务分组分别持久化为同目录的 `process-events.json`、`run-history.json` 与 `groups.json`，开启落盘的服务输出写入同目录 `logs/<服务名>.log`。这些数据不会上传；环境变量可能包含敏感信息，落盘日志可能包含业务内容，请只在可信本机使用。

## 已知限制

- 目前返回结果仍有上限，长时间扫描只会显示有限的匹配预览。
- 正则模式整行匹配，单行超过 4 MiB 会停止并提示改用普通文本检索。
- 进程优雅退出与进程树回收需要继续在 Windows、macOS、Linux 上验证；强制结束子进程不一定会自动结束它派生的所有后代进程。
- 性能基准使用合成日志。正式发布前应使用真实日志和目标硬件记录扫描吞吐、内存和磁盘 I/O。
- macOS 同时提供 Apple Silicon（arm64）与 Intel（amd64）安装包；Intel 包是在 Apple Silicon Runner 上交叉编译 darwin/amd64 得到的，未在真 Intel Mac 上跑过实机验证。安装包均未签名与公证，首次打开需要右键选择「打开」以绕过 Gatekeeper，或执行 `xattr -dr com.apple.quarantine` 移除隔离属性。
- 实时跟踪只适用于单字节换行编码（UTF-8、GB18030）；UTF-16 日志需先转换。文件被就地覆盖后按截断处理，并从新内容末尾重新载入。
- 自动重启只覆盖进程启动后的异常退出；可执行文件缺失等启动失败不会自动重试。健康检查目标由用户填写，可指向本机或内网地址，请确认目标可信。
- 上游就绪等待只对本次批量启动中确实被下游依赖的服务生效，且需要该服务配置健康检查；等待时间应大于探测间隔，否则可能在首次探测前就超时。
- 资源采样每 2 秒更新一次，只统计主进程、不含子进程；Windows 使用工作集，Linux/macOS 使用常驻集，macOS 依赖系统 `ps` 命令。
- HTTP 调试器默认跟随重定向（最多 10 次），跳转后的 3xx 响应需要关闭「自动跟随重定向」才能直接查看；跳过 TLS 校验只应在本机自签证书调试时开启。响应正文超过 2 MiB 时界面只保留前 2 MiB，二进制正文仅显示带替换字符的预览。
- 结果过滤与排序只作用于当前内存中的结果，不会更新文件内容；收藏按文件路径与行号记录，清理浏览器数据或更换系统用户后可能丢失，且仅对当前结果里出现的行生效。
- 聚合统计基于行内文本启发式识别级别（fatal/err 归入 error），没有级别词的容器日志会落入「其他」；签名 Top 5 只统计 error/warn 行，且仅覆盖当前已返回的结果。
